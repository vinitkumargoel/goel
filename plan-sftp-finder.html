Plan v1 · SFTP

Finder parity for the SFTP browser

Make Goel°'s remote file browser feel the way Finder feels — including copy, paste and move, both within a server and between two servers. In-app only: no volume mount, no File Provider extension.

Scope In-pane Finder feel Surface ~5,200 lines across 17 files libssh2 1.11.1 (vendored) Baseline main, CI green
!

The browser is feature-rich but architecturally unable to feel like Finder

Every single SFTP operation — every folder click, every rename, every stat — opens a fresh TCP connection, performs a full SSH key exchange, authenticates, initialises an SFTP channel, and tears the whole thing down. Nothing on the feature list below is worth building until that is fixed.

Framing note

  • macOS Finder has no native SFTP support. There is no sftp:// in Connect to Server — only SMB, AFP, NFS, WebDAV and read-only FTP. "The same experience I have in Finder" therefore means the feel of Finder as a file manager, reproduced inside Goel's own pane.
  • A literal Finder mount would need a File Provider extension, the com.apple.developer.fileprovider entitlement, a separate extension process, and a rewrite of SFTPClient into a long-lived session service. That is explicitly out of scope here.

0. Executive summary

The SFTP browser already does far more than a first look suggests: grid and list views, sortable listings, multi-select with modifier keys, full keyboard navigation, Quick Look, lazy drag-out to Finder, recursive folder upload with a conflict sheet, a live transfer strip with speed and ETA, host-key pinning with an approval sheet, and complete VoiceOver labelling. The feature gap to Finder is narrower than expected.

The experience gap is not, and it has one dominant cause. SFTPClient runs each operation via run() → runOnThread(), which spawns a thread that calls a gsb_* function; every one of those functions begins with gsb_open() (TCP connect, KEX, host-key verification, authentication, libssh2_sftp_init) and ends with gsb_teardown(). There is no session reuse anywhere in the codebase.

Concrete consequence. uploadFolder calls client.upload(...) once per file. Uploading a folder of 500 small files performs 500 complete SSH handshakes. On a 100 ms-RTT host that is minutes of pure cryptographic overhead moving no data.

The plan is therefore four phases, strictly ordered. Phase 1 introduces session reuse and ships nothing user-visible except speed. Phase 2 delivers the copy/paste/move work. Phases 3 and 4 close the metadata and polish gaps that only become affordable once round trips are cheap.

1. What the browser already does

Audit-verified against the source, not the changelog.

Navigation

Solid

List/grid toggle persisted via @AppStorage, clickable breadcrumbs that handle both absolute and home-relative paths, back/forward history (⌘[ ⌘]), parent (⌘↑), per-connection last-path memory with stale-path fallback, sort by name/size/date with folders pinned first, and a show-hidden toggle.

Selection

Finder-equivalent

Plain click, ⌘-click toggle, ⇧-click range from the cursor, ⌘A, Esc. Arrow keys move a cursor with ⇧ to extend and auto-scroll. Return opens or downloads, Space Quick Looks, Delete removes.

Transfers

Genuinely good

Drag-out registers a lazy file representation so nothing downloads until the drop is accepted, and cancelling the drag aborts the network transfer through a shared CancelFlag. Drops upload into the current folder or into a specific folder row. Folder uploads recurse. A conflict sheet offers rename/overwrite/skip. The transfer strip survives closing the browser.

Safety

Carefully built

Host keys pinned trust-on-first-use with a credential-free pre-flight so the password is never offered to an unverified host. Server-supplied names are validated by isSafeChildName before being joined onto any path. Byte caps bound drag-out and preview. Download shortfall is asserted against the file actually on disk. libssh2's misleading handshake strings are remapped to honest ones.

2.1 Structural

3. Decisions taken

Finder-feel in Goel's pane, or an actual Finder mount?

In-pane. No File Provider extension.

A mount is months of work behind an entitlement and a rewrite of the client into a session service. Every gap above can be closed in-pane and ships incrementally.

How far does the session-reuse fix go?

Full handle-based refactor of the C API.

A metadata-only fix leaves folder jobs handshaking per file. Since Get Info, folder sizes, recursive delete and folder download are all N round trips, half a fix is no fix.

One session with many channels, or many sessions?

Multiple TCP sessions, one per role.

Multiplexing channels over one session is kinder to the server and authenticates once, but requires driving every channel from a single thread with non-blocking I/O — which turns every blocking loop in ssh_bridge.c into an EAGAIN state machine. That is a rewrite of a working, CI-green file. Separate sessions reuse the existing blocking code almost unchanged, at the cost of a few extra authentications.

How is a same-server copy performed with no server-side copy primitive?

Relay through the local machine now; pluggable strategy so a server-side fast path can drop in later.

Adding libssh2_channel_exec to run cp -a would make same-server copies instant and free — but it introduces shell execution with user-supplied paths into a codebase that currently has no such surface, and it breaks on ForceCommand internal-sftp accounts anyway. Ship the universal path first behind a strategy protocol.

What does ⌘C put on the clipboard?

Full parity, both directions.

An internal clipboard carrying (connectionID, [remotePaths], intent) drives Goel→Goel across servers. An NSFilePromiseProvider gives Goel→Finder, and reading .fileURL gives Finder→Goel. Bindings match Finder: ⌘C, ⌘V, ⌘⌥V to move.

What proof is required before a move deletes the original?

Stat-verify the destination byte count, then delete.

Without a shell there is no cheap remote checksum — verifying content would mean reading the whole file back. A destination stat costs one round trip and catches truncation, short writes and out-of-space, which are the failures that actually occur. A folder's source subtree is deleted only once every file beneath it has verified.

Where do relayed bytes meet?

A bounded in-memory pipe.

The chosen topology already gives both sessions their own thread. The source's write callback fills a fixed ring buffer and the destination's read callback drains it, with backpressure in both directions. No temp disk, no size ceiling, and the upload starts immediately so wall-clock is roughly halved.

Decisions taken without asking

Cross-server UI

Clipboard + sidebar drop. No dual pane, no tabs.

The clipboard already makes ⌘C on server A / ⌘V on server B work. One cheap visual path is added: drag a selection onto another server's sidebar row to copy into its last-known folder. Finder has no split view, so a dual pane would be less Finder-like, not more. Tabs are deferred, not dropped.

Trash

None. Undo instead.

SFTP has no trash, and inventing a ~/.Trash convention would be a lie that breaks on read-only mounts and quota'd homes. Instead: a real ⌘Z stack for rename, move and new-folder — each reversible with a single rename. Delete stays permanent behind a confirm sheet that says so plainly.

Recursive delete

Yes, with a pre-scan.

The confirm sheet shows "412 items · 8.3 GB" counted over the background session before you commit. Deleting blind is how people lose data.

Symlinks

First-class, with a cycle guard.

lstat + readlink in the bridge: link badge in the listing, target in Get Info, resolve-on-open. A loop guard on every recursive walk — otherwise the first symlink cycle turns a folder download into an infinite one.

Get Info

Includes chmod. Owner stays numeric.

Permissions as octal and rwxr-xr-x, size, dates, link target, full remote path. Owner and group are shown as raw uid/gid — SFTP gives no name mapping without a shell, and inventing one would be a fabrication.

Caps

Keep for preview, raise for drag-out.

Quick Look is a peek and 512 MB is a sane ceiling. Drag-out becomes a real transfer with a progress row and a cancel button, at which point an arbitrary limit stops making sense. Browser downloads also route through the resumable engine path.

4. Session architecture

Today

every single operation SFTPClient.run() └─ Thread { withAuth { gsb_list(auth, path, …) } } │ ├─ gsb_open() │ ├─ TCP connect 1 RTT │ ├─ SSH banner + KEX 2–3 RTT + crypto │ ├─ host-key verify │ ├─ authenticate 1–2 RTT │ └─ libssh2_sftp_init() 1 RTT ├─ …the actual work… 1 RTT └─ gsb_teardown() folder upload, 500 files = 500 × the whole column above

After Phase 1

SFTPSessionActor(connection) serial command queue per session │ ├─ interactive list · stat · mkdir · rename · remove │ never blocked by a scan or a transfer │ ├─ background recursive walks · folder sizes · thumbnails │ delete pre-scans · search │ └─ transfer[job] one session per JOB, not per file a 500-file folder = 1 handshake each session: one dedicated pthread, owns its LIBSSH2_SESSION for life, drains a command queue, reconnects transparently on drop, closes after an idle timeout
Server load. A busy user could hold 3–4 authenticated connections to one host. OpenSSH's default MaxStartups (10:30:100) accommodates this comfortably, but the session manager will cap concurrent sessions per server and queue beyond it, so a strict server cannot be tripped by a burst of thumbnail requests.

5. Copy engine

One engine serves same-server copy, cross-server copy, cross-filesystem move, and the paste half of the clipboard. It is defined by a strategy protocol so the server-side fast path can be added later without touching a single call site.

protocol CopyStrategy { func canHandle(source: Endpoint, destination: Endpoint) -> Bool func copy(_ item: RemoteItem, to: RemotePath, progress: …) async throws } RelayStrategy — ships in Phase 2, handles everything ExecStrategy — later, same-server only, requires a shell probe NativeStrategy — later, needs copy-data@openssh.com in libssh2

The relay path

source session bounded ring buffer dest session ────────────── ─────────────────── ──────────── gsb_download ──write cb──▶ [████████░░░░░░░░] ──read cb──▶ gsb_upload (thread A) backpressure (thread B) both directions cancel ─▶ CancelFlag observed by BOTH progress callbacks stall ─▶ watchdog on buffer age; neither side can deadlock done ─▶ stat destination · byte count must match · then delete source

Move semantics, in order of preference

  1. Same server, same filesystem — a single rename. Instant, atomic, no data moves. This is what exists today.
  2. Same server, different filesystem — rename fails with SSH_FX_FAILURE; fall back to relay copy, stat-verify, delete source. This case fails outright today.
  3. Different servers — relay copy, stat-verify, delete source. No other option without agent forwarding.
Partial-failure policy. A folder move interrupted halfway is not rolled back. Both sides are left intact and the result sheet states exactly what moved and what did not. Automatic rollback of a partially-completed move is how a failed operation becomes a data-loss event.

6. Bridge API changes

The C surface grows from 8 operations to a handle-based API plus 5 new calls.

New session lifecycle
GSBSession *gsb_session_open(const GSBAuth *auth, GSBResult *r); void gsb_session_close(GSBSession *s); int gsb_session_alive(GSBSession *s); // keepalive probe

Every existing gsb_* loses its const GSBAuth *auth first parameter and gains GSBSession *s. gsb_open and gsb_teardown become internal to the session lifecycle rather than being run per call.

New operations
GSBResult gsb_lstat(GSBSession *s, const char *path, GSBStat *out); GSBResult gsb_readlink(GSBSession *s, const char *path, char *buf, size_t cap); GSBResult gsb_setstat(GSBSession *s, const char *path, unsigned long perms); GSBResult gsb_statvfs(GSBSession *s, const char *path, GSBSpace *out); GSBResult gsb_realpath(GSBSession *s, const char *path, char *buf, size_t cap);

All five map directly onto libssh2 1.11 functions that already exist and are already linked — libssh2_sftp_stat_ex with LIBSSH2_SFTP_LSTAT, libssh2_sftp_symlink_ex with READLINK and REALPATH, libssh2_sftp_setstat, and libssh2_sftp_statvfs. No libssh2 patching required.

Extended listing callback
typedef void (*gsb_entry_cb)(void *userdata, const char *name, int is_dir, long long size, long long mtime, unsigned long perms, int is_link, const char *link_target, unsigned long uid, unsigned long gid);

SFTPEntry gains isSymlink, linkTarget, uid and gid. Its existing permissions field — already populated, never displayed — finally gets used by Get Info.

Blast radius. Every call site changes: SFTPClient, SFTPEngine, SFTPSession, the CLI's doctor path, and the Linux daemon. The C file itself is 548 lines and the per-call open/teardown pairs are already cleanly factored, so the mechanical change is contained — but it must land in one commit to keep the build green.

7. Phases

1

Sessions no visible features

The handle-based C refactor, the session actor, role-based session allocation, idle timeout, and transparent reconnect on drop. Ships as pure speed.

  • gsb_session_open / _close / _alive; all ops take a handle
  • Dedicated pthread per session draining a serial command queue
  • Roles: interactive · background · one per transfer job
  • Folder upload rewired to reuse one session for the whole job
  • Per-server concurrent-session cap with queueing

Cannot be parallelised. Everything else depends on it.

2

Copy, paste, move the requested work

The CopyEngine and the full clipboard, same server and across servers.

  • CopyStrategy protocol; RelayStrategy with the bounded pipe
  • Stat-verify before source deletion; cross-filesystem rename fallback
  • Recursive folder download (mirroring uploadFolder)
  • Recursive delete with a pre-scan count and size
  • ⌘C / ⌘V / ⌘⌥V; internal clipboard + NSFilePromiseProvider + .fileURL read
  • Drag onto a sidebar server row for cross-server copy
  • Undo stack for rename, move and new-folder
3

Finder metadata bridge work

The five new bridge calls and the surfaces that consume them.

  • Symlink badges, targets, resolve-on-open, and cycle guards on every walk
  • Get Info sheet (⌘I) with chmod write-back
  • Free space in the status footer via statvfs
  • Folder size calculation on the background session
4

Finder feel polish

The remaining differences, each individually small.

  • Image thumbnails, lazily fetched on the background session, LRU-cached to disk
  • Inline rename replacing the modal alert
  • Sortable, resizable column headers including Kind
  • Type-ahead selection; ⌘⇧G go-to-path
  • ⌘⌫ ⌘I ⌘D ⌘⇧. ⌘↓
  • Remote-folder favourites in the sidebar; recursive background search
  • Raise the drag-out cap; route browser downloads through the resumable path

8. Risks

RiskSevMitigation
Relay pipe deadlock P0 Two blocking C loops with mutual backpressure can wedge if either side stalls. A watchdog on buffer age aborts both; the CancelFlag is observed by both progress callbacks; cancellation is tested against a deliberately stalled server.
Session refactor regresses the queued engine P0 SFTPEngine and the resumable download path share SFTPClient. The existing SFTPSessionTests, sftpRemediationTests and sftpFailOpenRemediationTests must pass unchanged before anything else lands.
Symlink cycles P1 Recursive download, recursive delete, folder sizing and search all walk the tree. Each carries a visited-inode set and a depth cap. Today's code cannot hit this only because it cannot see symlinks at all — making them visible creates the hazard.
Host-key trust across many sessions P1 Opening 3–4 sessions per server must not mean 3–4 approval prompts, nor a race where two first-contact probes both pin. The approval is resolved once per server per app run, ahead of session creation, and the pin is written under a lock.
Reconnect during a mutation P1 A dropped session that transparently reconnects must not silently replay a half-applied rename or remove. Mutations are never auto-retried across a reconnect; they surface the failure and the browser re-lists.
Thumbnail fetch storms P2 Scrolling a 2,000-file folder must not queue 2,000 downloads. Requests are bounded, cancelled on scroll-away, size-capped, and served from the disk LRU first.
Pasteboard file promises P2 NSFilePromiseProvider paste into Finder has historically been unreliable. Drag-out already works and stays the primary path; if promise-paste proves flaky it degrades to a no-op with a toast rather than a hang.

9. Test plan

Phase 1

Session lifecycle

Handshake count assertions — a 50-file folder upload must perform exactly one. Idle timeout closes. Reconnect after a killed connection. Serial ordering under concurrent submission. Existing SFTP test suites pass unmodified.

Phase 2

Copy engine

Byte-exact relay of a file larger than the ring buffer. Cancel mid-relay leaves no partial destination. Stat-verify rejects a truncated destination and refuses to delete the source. Cross-filesystem rename falls back correctly. Interrupted folder move reports precisely what moved.

Phase 3

Metadata

Symlink to file, to directory, dangling, and cyclic — each renders correctly and each recursive walk terminates. chmod round-trips. statvfs against a server that does not support the extension degrades silently.

Throughout

Adversarial listings

The existing isSafeChildName guards must extend to every new path consumer: copy destinations, move targets, thumbnail fetches, recursive walk children, and clipboard paste. A hostile listing must not escape the browsed tree by any of the new routes.
